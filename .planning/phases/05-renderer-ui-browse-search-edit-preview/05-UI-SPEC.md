# Phase 5 — UI Design Contract

> Visual and interaction contract for the renderer loop: summary → browse/search → edit (inline validation) → preview → confirm → non-destructive write. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Context (why these choices)

This is a **single-window, single-user, non-distributed local desktop tool** for one early-access game tester. The renderer runs under a **strict CSP** (`default-src 'self'; script-src 'self'` in `electron/index.html`), which blocks remote resources and runtime `<style>` injection (CSS-in-JS). Every completed phase (1–4) logged a "least-privilege / zero-added-deps" stance, and CLAUDE.md explicitly rejects heavy state/UI libraries.

Consequences baked into this contract:

- **No design-system framework** (no shadcn, no Tailwind). Styling is a single bundled plain-CSS stylesheet with CSS custom-property tokens, emitted by the existing esbuild pipeline and loaded from `'self'` — CSP-safe, zero heavy deps.
- **Data-dense, keyboard-first desktop layout.** A save has ~689 bank item stacks and ~30+ skills, so both browse lists are virtualized (`@tanstack/react-virtual`, already in the approved stack) with a fixed row height.
- **The data + IPC contract is already frozen by Phase 4** and must be consumed as-is (see "Data & Interaction Contract" below). The UI adds no new IPC surface.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (plain CSS + CSS custom-property tokens, bundled by esbuild) |
| Preset | not applicable |
| Component library | none (hand-rolled React 19 components) |
| Icon library | none — inline SVG or Unicode glyphs only (CSP-safe, no dep/network) |
| Font | System UI stack for text; system monospace stack for numeric/ID columns |

**Font stacks (declare in `:root`):**
- Text: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`
- Mono (currencies, XP, quantities, namespaced IDs): `ui-monospace, "Cascadia Code", "Segoe UI Mono", Menlo, monospace`

**shadcn gate:** executed. `components.json` absent; stack is React + esbuild. Resolved to `none` because (a) strict CSP blocks CSS-in-JS runtime injection, (b) the tool is a non-distributed solo utility, and (c) every prior phase locked a zero-added-heavy-deps decision. Registry safety gate is therefore not applicable.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps, inline control padding, gap between a value and its unit |
| sm | 8px | Compact spacing inside rows, input padding, gap between adjacent controls |
| md | 16px | Default gap between fields, panel inner padding, summary-item spacing |
| lg | 24px | Panel padding, gap between the two list panels |
| xl | 32px | Top-level layout gutters, gap between summary bar and browse area |
| 2xl | 48px | Empty-state vertical breathing room |
| 3xl | 64px | Reserved (page-level spacing) — likely unused in a single-window tool |

**Exceptions:**
- Virtualized list **row height fixed at 32px** (`--row-h: 32px`) — required by `@tanstack/react-virtual` `estimateSize`; must stay constant per list for correct virtualization.
- Interactive controls (inputs, buttons, filter fields) minimum height **32px** (desktop pointer + keyboard; 44px touch targets not required).

## Typography

Exactly 4 size roles, exactly 2 weights (400 regular, 600 semibold).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Summary value | 20px | 600 | 1.2 |
| Heading (panel titles) | 16px | 600 | 1.2 |
| Body (rows, inputs) | 14px | 400 | 1.5 |
| Label (column headers, captions, helper/error text) | 12px | 600 | 1.4 |

**Rules:**
- Numeric columns and namespaced IDs render in the **mono** stack at Body 14px so digits align for scanning across 689 rows.
- Summary values (GP, Slayer Coins, Total Level) render mono 20px/600 — GP/Slayer Coins are int64 strings and must never be reformatted into a JS number.
- Column headers (Label 12px/600) are uppercase with `letter-spacing: 0.04em`; helper and inline-error text reuse Label 12px (color distinguishes them — see Color).

## Color

Light neutral base, single blue accent, single red for problems. 60 / 30 / 10 discipline.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Editing surface, list row background, input fields, main content area |
| Secondary (30%) | `#F1F5F9` | Summary bar, panel/column headers, toolbars, preview panel surface, zebra alt-row |
| Accent (10%) | `#2563EB` | See reserved list below |
| Destructive | `#DC2626` | Inline validation error text + input border; error banners (see note) |

**Supporting neutrals (not counted in the 60/30/10 split — text + lines):**
- Primary text `#0F172A` · Muted/secondary text `#64748B` · Borders/dividers `#E2E8F0` · Focus ring uses Accent at 40% alpha.

**Accent reserved for (explicit list — never "all interactive elements"):**
1. The primary CTA button fill (`Write New Save File`).
2. The keyboard focus ring on the currently-focused input/button/row.
3. The active/edited-row left indicator (a 2px accent bar marking rows with a pending edit).
4. The pending-changes count badge on the Preview control.

All other interactive elements (filter inputs, secondary buttons, list rows) use neutral surfaces + borders; hover is a neutral tint (`#F8FAFC`), not accent.

**Focal point:** The summary bar's GP / Total Level values are the primary visual anchor on load; after an edit, focus shifts to the accent-marked edited rows and the pending-changes badge / `Preview Changes` CTA.

**Destructive note:** This phase has **no destructive action** — the write is non-destructive by design (new file; original never touched). Red is therefore reserved strictly for *problem states*: inline value validation errors and the write/parse error banner. Do not use red for the write button. Write-success (output path shown) uses neutral text + a Unicode check glyph — no new green token, to preserve the 10% accent discipline.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Write New Save File` |
| Secondary CTA (open) | `Open Save File…` |
| Secondary CTA (preview) | `Preview Changes` |
| Skill edit mode toggles | `Set by level` · `Set XP` |
| Empty state heading | `No save loaded` |
| Empty state body | `Open a Melvor Idle 2 .sav file to browse and edit its contents.` (renders the `Open Save File…` button beneath) |
| Filter empty-result heading | `No matches` |
| Filter empty-result body | `No items match "{query}". Clear the filter to see all items.` (skill list swaps "items"→"skills") |
| Inline validation error | `Value must be between {min} and {max}.` (int32/int64) · `Level must be between 1 and {levelCap}.` (skill level) · `Enter a whole number.` (non-integer) |
| Load/parse error state | `Couldn't read this save file. It may be from an unsupported game version. Choose a different .sav file.` |
| Write error state | `Write failed: {message}. Your original file was not changed.` (covers `write-invariant`, `no-session`, `internal` kinds) |
| Write confirmation | `Write New Save File`: `Creates a new .sav next to the original — your original file is never changed. Write {n} pending change(s)?` |
| Write success | `Saved to {outputPath}` (with a ✓ glyph, neutral color) |
| No-op preview | `No pending changes.` (Preview control disabled until at least one edit differs from its loaded value) |

**Copy rules:** No em-dash-free jargon leaks — surface `kind` messages only inside the framed error copy above, never raw. Currency/XP values in confirmation and preview text render mono and are never reformatted (int64 stays a string).

## Data & Interaction Contract (frozen by Phase 4 — consume as-is)

The UI is a pure projection of the Phase 4 IPC bridge (`window.saveEditor`). It adds **no** new IPC channel and must not touch Node/fs/Brotli/offsets.

**Bridge methods & result shapes:**
- `load()` → `{ ok:true, summary }` | `{ ok:true, cancelled:true }` | `{ ok:false, kind, message }`
- `getModel()` → `{ ok:true, viewModel }` | `{ ok:false, kind:'no-session' }`
- `preview(edits)` → `{ ok:true, changeReport: WireChangeRow[] }` | error
- `write(edits)` → `{ ok:true, outputPath }` | `{ ok:true, cancelled:true }` | error

**Shapes the UI renders:**
- `ViewModel`: `{ version, unknownVersion, summary{ name, gamemode, totalLevel, gp:string, slayerCoins:string }, bankItems[]{ itemId, quantity, isPlaceholder, isLocked }, skills[]{ id, xp, level, levelCap }, entityIds[], unresolvedFields? }`
- Edit payload element: `{ fieldKey, newValue: string|number }` — int64 (`wallet.GoldPieces`, `wallet.SlayerCoins`) crosses as a **decimal string**; int32 quantity / double XP / int32 level cross as numbers.
- `WireChangeRow` (preview/confirm table): `{ fieldKey, oldValue, newValue, width }` — old→new, no offset.
- Error `kind`s to map to copy: `validation` (+`violations[]`), `readonly`, `unknown-field`, `conflict`, `bad-args`, `write-invariant`, `no-session`, `internal`.

**Interaction states each component must define:** loaded-empty (no save), loading (async bridge call in flight — disable CTAs), populated, filtered-empty, field-editing (dirty), field-invalid (inline error, contributes no edit), preview-open, write-success, write-error. `unknownVersion:true` shows a non-blocking warning banner ("Newer save version than tested — parsed anyway; review changes carefully.") but does not block editing.
