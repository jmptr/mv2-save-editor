<objective>
Build the one place structural descent doesn't suffice: the Bank **Inventory** item stacks, nested into named tabs. Implement the research's bounded marker-search + '6-bytes-before-the-length-prefix' + context-validation, scoped to the Inventory component byte region, recovering all 689 stacks a naive contiguous walk misses (it stops at ~296 at the first tab boundary). Each valid hit becomes a stack FieldEntry keyed by its qty offset (SC-1), gated by the SC-3 context-validation that rejects false matches, and the D-03 ambiguity contract for a single logical field resolving to multiple offsets.

Purpose: Delivers the bank-item half of SC-1 and the item-stack half of SC-3 (context-validation + ambiguity-surfaced-not-auto-picked). This is the trickiest correctness surface in the phase.

Note (provisional decision in play): D-03's ambiguity contract (resolve-one / candidates-when-many / fail-loud-when-zero) is PROVISIONAL. This plan treats multiple stacks of the same item across tabs as distinct offset-keyed fields (NOT ambiguity), and reserves the candidate path for a single logical field. If the user later wants per-tab grouping or a different duplicate policy, only this parser and the Wave 3 projection change.

Output: `src/inventory-parser.ts`, `test/inventory-parser.test.ts`.
</objective>
