### `electron-builder.json` (config, transform) — NEW-OF-KIND

**Analog:** None in codebase. Closest structural sibling is `package.json` (a root-level JSON config
the tooling reads). **Content shape is fully specified in `06-RESEARCH.md` Pattern 1 (lines 150–175).**

**Why `.json` not `.yml`:** RESEARCH Validation Architecture (lines 399) — `.json` is `require()`-assertable
in `node:test` with zero deps; `.yml` would force a YAML parser into the tests. CONTEXT D leaves this to

format: `directories.output: "release"` (NOT `dist` — esbuild owns `dist/`), and `files` must include
`dist/**` so preload.js/index.html stay siblings of main.js inside the asar.

Required keys (from RESEARCH, locked by CONTEXT D-01/D-02/PKG-03/PKG-04):
```
appId: "com.jmptr.mv2-save-editor"     (D-02 — stable AppUserModelID)

```
Every fs/zlib/path import in this repo is `node:`-prefixed. New files must follow.

### node:test harness (NOT Vitest)
**Source:** `test/scaffold.test.ts` (whole file), `package.json` line 18 (`"test": "tsx --test 'test/**/*.test.ts'"`)
**Apply to:** all three new `test/packaging.*.test.ts` files.
```ts
import { describe, test } from 'node:test';
import assert from 'node:assert/strict';
```
CLAUDE.md mentions Vitest but the actual repo uses `node:test` run via `tsx`. Match the repo, not CLAUDE.md.
New test files must match the `test/**/*.test.ts` glob to be picked up by `npm test`.

### Explanatory top-of-file doc comment
**Source:** `scripts/build.mjs` lines 1–16, `test/codec.test.ts` lines 1–16, `test/primitives.test.ts` lines 1–18
**Apply to:** `scripts/make-icon.mjs` and all new tests.
Every non-trivial file in this repo opens with a block comment stating what it does, what it proves, and
which decisions/requirements it implements (e.g. reference PKG-01..04). Continue this convention.

### Safe binary reads (no raw indexing)
**Source:** `test/primitives.test.ts` line 12 (`noUncheckedIndexedAccess — uses readUInt8 not buf[i]`)
**Apply to:** `test/packaging.icon.test.ts` (ICO header parsing) and `scripts/make-icon.mjs` (uses
`writeUInt32LE`/`writeInt32LE`/`writeUInt16LE`/`writeUInt8`, matching the project's DataView-style writes).
