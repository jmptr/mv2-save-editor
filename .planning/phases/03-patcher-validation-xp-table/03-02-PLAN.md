<objective>
Build the same-width, in-place patch engine `src/patcher.ts`:
`patchSave(buffer, fieldTable, edits) -> { buffer, changeReport }` (D-04). It resolves each edit to
its FieldEntry by key, validates every value against its type/range (SAFE-01), rejecting rather than
clamping (fail-loud); expands skill level/xp edits into their coupled pair via the plan-03-01
experience-table (EDIT-04); writes onto a `Buffer.from(input)` copy with `writeBigInt64LE /
writeInt32LE / writeDoubleLE` at the FieldEntry offset (SC-1 by construction); then self-verifies by
re-parsing and whole-buffer-diffing so only intended byte ranges can have changed (SC-4, D-03).

The whole batch is validated first — if any edit fails, a typed ValidationError enumerating ALL
violations is thrown and NOTHING is written (D-01, atomic). LevelCap and header mirrors are readOnly
and rejected as targets. Currency is bigint end-to-end (never Number).

Purpose: SAFE-01 (validate every value before writing) and EDIT-04 (target-Level -> consistent
XP+Level) are the phase's correctness gates; corruption is the worst outcome, so the safety check is
intrinsic to the write, not test-only.
Output: `src/patcher.ts` + `test/patcher.test.ts` (RED-first, then GREEN).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller edits {fieldKey, newValue} -> patch write path | Untrusted values enter the write boundary; a bad value must be rejected before any byte changes (SAFE-01) |
| FieldTable offsets -> buffer copy | An off-by-one offset or wrong-width write could clobber an adjacent field; the self-verify diff is the backstop (SC-4) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Tampering | patchSave value inputs (validation) | high | mitigate | Pre-write range/type validation per FieldKind (SAFE-01); collect ALL violations then write nothing on any failure (D-01); out-of-range REJECTED, never clamped |
| T-03-03 | Tampering | applyWrite at FieldEntry offset | high | mitigate | Same-width writeXxxLE on a Buffer.from(input) copy (length-neutral, SC-1); whole-buffer self-verify diff throws UnintendedChangeError on any byte outside [offset,offset+width) (D-03) |
| T-03-04 | Tampering | int64 currency write | high | mitigate | bigint end-to-end via writeBigInt64LE — never Number, never writeDoubleLE for currency (precision loss above 2^53; threat continuity T-02-06) |
| T-03-05 | Tampering | readOnly targets (LevelCap / header mirror) | medium | mitigate | Reject any edit whose FieldEntry.readOnly is true (ReadOnlyFieldError) — LevelCap and header GP/SC mirrors are never write targets |
| T-03-06 | Tampering | non-finite XP written as double | medium | mitigate | Number.isFinite(xp) && xp >= 0 guard before write; NaN/Infinity rejected as a ValidationError |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | No packages installed this phase (pure Node core + in-repo modules); RESEARCH §Package Legitimacy Audit confirms "not applicable" |
</threat_model>
