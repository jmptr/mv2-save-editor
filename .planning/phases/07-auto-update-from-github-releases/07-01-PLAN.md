<objective>
Wire `electron-updater@^6.8.9` into the build so it ships physically inside `app.asar` and resolves
from `node_modules` at runtime, and give the GitHub-Releases provider a deterministic feed. This is the
"packaging half" of the phase — three one-shot config edits (per D-06 + D-07) plus a static-assertion
test that pins them against the acceptance bar. It carries a blocking supply-chain legitimacy gate
because `electron-updater` is the only new runtime dependency and the packaged app executes a
downloaded installer (threat T-07-SC).

Purpose: satisfy ROADMAP success criterion 4 (electron-updater physically in `app.asar` + listed in
esbuild `external`) and the feed-resolution precondition for UPD-01/UPD-02, without touching the
lean `files: ["dist/**", "package.json"]` glob (production deps are auto-included in the asar).

Output: `electron-updater` under `dependencies`; `scripts/build.mjs` `external` extended; an explicit
`publish` block in `electron-builder.json`; `test/updater.packaging.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → local node_modules | A new third-party runtime dependency (`electron-updater`) crosses into the app's trusted code and will ship inside `app.asar` |
| build config → app.asar | electron-builder decides (from `dependencies` + `publish`) what ships and what feed the updater trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-SC | Tampering | `npm install electron-updater` | high | mitigate | Blocking-human legitimacy checkpoint (Task 1) before install; pin `^6.8.9` (canonical electron-userland, `latest` dist-tag, no postinstall); commit `package-lock.json`. Never auto-approved. |
| T-07-02 | Tampering / Info Disclosure | GitHub Releases feed provider config | medium | mitigate | Explicit `publish` block (github/jmptr/mv2-save-editor) removes feed-resolution ambiguity; electron-updater fetches the feed over HTTPS by default (no plaintext `setFeedURL`). |
| T-07-06 | Denial of Service | esbuild bundling of electron-updater | medium | mitigate | Keep `electron-updater` in esbuild `external[]` so its dynamic requires / `app-update.yml` path resolution are not broken by bundling (Pitfall 4). |
</threat_model>
