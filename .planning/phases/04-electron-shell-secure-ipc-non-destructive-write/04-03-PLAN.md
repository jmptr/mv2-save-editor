single in-memory active session, D-02) and `src/ipc/write-service.ts` (the non-destructive

they run under `tsx --test` with no Electron runtime — this is where IO-02 is actually proven.

The write path reuses the exact invariant the codec/patcher already enforce: patch (which
self-verifies internally) → re-parse the patched buffer fresh (D-02) → assert
`output.length === input.length` (IO-02 / IO-03) → derive `<base>-edited.sav` → native Save-As →
reject the source path as a target (D-03) → `compress` (existing codec, standard-param Brotli) →
write the NEW file. The original bytes are never touched; a cancel is a clean no-op.

Purpose: the IO-02 guarantee, headlessly testable. Output: `src/ipc/session.ts` +
`src/ipc/write-service.ts` + two test files.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| main core → filesystem (write) | The patched buffer is recompressed and written to a user-chosen path. |
| renderer state → main state | Renderer's view of the session is never trusted; main operates on its own held FieldTable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-04 | Tampering / Repudiation | performWrite (output path) | critical | mitigate | Write only to a NEW path from `showSaveDialog`; reject `resolve(picked) === resolve(source)` with WriteInvariantError; the original file is never opened for write (D-03). |
| T-4-09 | Tampering | write path (length invariant) | high | mitigate | Re-parse the patched buffer fresh (D-02) and assert `output.length === input.length` BEFORE compress; patchSave self-verifies internally (belt-and-suspenders, IO-02/IO-03). |
| T-4-05 | Denial of Service | session.open (decompress) | medium | mitigate | `decompress` enforces `MAX_DECOMPRESSED_BYTES` (256 MiB) — inherited from the existing codec; a crafted bomb `.sav` throws rather than exhausting memory. |
| T-4-10 | Tampering | main trusting renderer state | medium | mitigate | SessionStore holds main's own freshly-parsed FieldTable; preview/write resolve every edit against it, never a renderer-supplied model (SC-4). |
</threat_model>
