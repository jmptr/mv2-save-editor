<objective>
The manual runtime acceptance gate for the phase: prove on real GitHub + real Windows the truths the
any-OS static test (Plan 08-01) cannot observe. Two milestones: (1) a real `v*` tag push produces a
DRAFT Release carrying `.exe` + `latest.yml` + `.blockmap`, the draft is invisible to the updater
until a human publishes it (CI-01/02/03 runtime); (2) the end-to-end two-release self-update proof
(SC4) — install v1.1.0, publish a v1.1.1 bump, and observe the installed v1.1.0 client detect →
download → apply the update and relaunch as v1.1.1.

Purpose: close the runtime half of CI-01/02/03 and deliver SC4, the whole reason auto-update lives in
Phase 8 (it is only fully observable across two sequential published releases). This mirrors the
Wave-2 manual Windows gates of Phases 6 (06-03) and 7 (07-03), which inherit the same Wine constraint:
the `.exe`/asar can only be produced/installed on Windows.

This plan also performs the single automatable code change the phase requires — the v1.1.1 version
bump — and encodes the Version=Tag invariant + the `test/packaging.config.test.ts` lockstep coupling
where that bump happens.

Output: the v1.1.1 bump (package.json + test in lockstep) and a recorded acceptance note in the
SUMMARY.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases feed → installed client | The published `latest.yml` + `.exe` are downloaded and the installer is executed by electron-updater on the user's Windows machine |
| draft vs published release → updater | Only a PUBLISHED release is visible to electron-updater; the draft state is the human gate |
| unsigned installer → Windows user | SmartScreen presents an "unknown publisher" prompt for the unsigned `.exe` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-06 | Tampering | downloaded update installer binary | high | mitigate | electron-updater verifies the downloaded `.exe` sha512 against `latest.yml` before applying (built-in, from Phase 7); confirmed working by the SC4 two-release apply |
| T-08-04 | Tampering | unintended / premature publish | high | mitigate | Draft-then-manual-publish (CI-03): CI only creates a draft; a human explicitly clicks Publish for both v1.1.0 and v1.1.1 |
| T-08-08 | Tampering (integrity) | version/tag mismatch → assets on the wrong release | medium | mitigate | Version=Tag invariant enforced by the lockstep bump + `npm test` (line 39) and by pushing `v${version}`; RESEARCH Open Q1 optional guard step available |
| T-08-07 | Spoofing (user trust) | unsigned installer / SmartScreen | low | accept | Documented + accepted (REQUIREMENTS Out-of-Scope); code signing deferred to v2 (DIST-03); updater sha512 integrity is still enforced on the delta |
</threat_model>
