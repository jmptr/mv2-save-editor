<objective>
Create the single tag-triggered GitHub Actions workflow that automates the already-proven local
`build:electron → electron-builder --win → GitHub Release` chain, plus the zero-dep static test that
pins its load-bearing contract. This is the automatable, any-OS slice of the whole phase: CI-01
(trigger + host + Node + build-before-package), CI-02 (publish assets with `contents: write` +
`GH_TOKEN`), and CI-03 (default-draft, no forced-publish override) are all expressed as workflow
config and asserted by text so the contract cannot silently drift.

Purpose: give the developer a `v*`-tag → draft-Release pipeline that mirrors the local `package`
script exactly (only additions: `--publish onTagOrDraft` and the `GH_TOKEN` env). The STATE-flagged
#1 first-CI risk — the `@esbuild/win32-x64` platform-binary resolution on `windows-latest` — is
de-risked by inspection (the lockfile already carries it) and guarded here by a lockfile-coverage
assertion that fails loudly if a future `npm install` on Linux ever strips it.

Output: `.github/workflows/release.yml` and `test/release.workflow.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer push → GitHub Actions runner | A `v*` tag push (repo-write-gated) starts a workflow that runs with the ephemeral `GITHUB_TOKEN` |
| GitHub Actions runner → GitHub Releases | electron-builder uses the token to create/upload release assets (`contents: write`) |
| third-party action → CI runner | Any action referenced by the workflow executes with the job's token/permissions |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | workflow `GITHUB_TOKEN` scope | high | mitigate | `permissions: contents: write` ONLY (no `write-all`, no PAT); asserted by `test/release.workflow.test.ts` (Task 2) |
| T-08-02 | Tampering | third-party / repointed GitHub Action | high | mitigate | Only first-party `actions/*` pinned to `@v4`; no marketplace action; test asserts `actions/checkout@v`/`actions/setup-node@v` |
| T-08-03 | Information Disclosure | `GH_TOKEN` leaked via logs | high | mitigate | Token passed via `env:` only, never `echo`ed; GH masks secrets in logs; test asserts no `run:` step prints the token |
| T-08-04 | Tampering | unintended publish on non-tag push | high | mitigate | `on: push tags: ['v*']` + `--publish onTagOrDraft`; test asserts trigger is tag-only and no `--publish always` |
